## Primary Intent: Enforce Static-Site and Local-First Architecture

### Mission Statement

The goal is user sovereignty and decentralization, achieved by strictly separating the local application (the "engine") from the public profile (the "artifact"). The engine does all dynamic work: authoring, signing, syncing with peers, building the feed and publishing. The artifact is static files with no server-side logic, hostable on any static host. Keep this boundary in all design and code.

### Goals

- Static artifact. The public site is static files only (HTML, CSS, client-side JS, signed JSON, media), with no server-side code, database or API. Client-side JS may render the bundled signed JSON. Third-party scripts (analytics, ads, comments) only as opt-in add-ons, off by default.
- Pull federation and identity. did:web plus an Ed25519 key pinned on first use. Peers are added by site URL. Sync means fetching signed static JSON. No live connections.
- Signing and verification. Every published document is signed. Unverified peer data is never re-published. Only verified fetches may delete local data.
- Nothing private leaves the engine. The export never contains private keys, private friends, local file paths, the peer feed, or mute/block lists. Peer endorsements are published only when the user has enabled publishing them and their signature has been verified.
- Moderation. Keyed by site URL. Mute = local feed only. Block = don't crawl, and don't publish their endorsements.
- Local state and automation. SQLite per persona. Personas never share data. The MCP CLI and HTTP endpoint are trusted local surfaces and must not be reachable from web pages.
- Publishing. Generate, then deploy (local folder, SFTP/FTP, GitHub Pages). Each publish records a snapshot time.
